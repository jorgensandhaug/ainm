The YOLO model performs well on bbox detection, but does not do so well on classification. Therefore, we had an idea to extract the cropped images from the YOLO model to a separate classifier model. The classifier can be trained both on ground truth extractions from the train dataset, extracted crops from the YOLO model on the train dataset. Additionally, there are some images of the products against a clean background. These do not entirely align with the cropped distribution, as they are more messy, but they might be helpful. To use them, you need to map from product name to class name to class id using json metadata. This mapping is not entirely complete, so you will not get product images for all classes.

There are two main strategies for an external classifier. It can either be a model that runs the image and outputs the class directly, or a model that has precomputed embeddings for different classes and then use FAISS or some variant of nearest neighbor against the embeddings of the crops during testing to find the correct class. However, a big challenge here is ensuring that the pipeline is fast enough. To optimise the score, the YOLO model uses a low threshold and creates many bounding boxes. If the classifier needs to be run on every crop, it might pose an issue. To alleviate it, the classifier must either be very fast, or we must select a subset of crops to perform re-classification on. It is then important to pick those where we believe the YOLO backbone fails on classification.  The validation is done on a remote server with an L4 GPU. The YOLO backbone alone completes it in roughly 20 seconds. This should give you an estimate of how many images it is run on, and how much time you can spend reclassifying/post-processing. The submission must complete in 300 seconds, but preferably with some margin.
