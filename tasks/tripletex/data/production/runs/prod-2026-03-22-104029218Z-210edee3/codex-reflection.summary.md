## 4. Root Causes

1. **Redundant PDF upload**: The trusted standard explicitly included a "Step 4: Upload PDF Attachment" section with code. The agent followed it faithfully. The root cause is the trusted standard itself was wrong — it was written before we knew `importDocument` auto-generates a PDF. Sandbox verification (this reflection) proved the attachment field is populated after importDocument alone (`mimeType=application/pdf`, ~51KB auto-generated).

2. **Overcounted writes in standard header**: The flow header said "6 writes + free GETs" but actually had 5 writes (the GET /ledger/account was miscounted as a write). This led to confusion about the true write count. Fixed to "4 writes + 1 required GET".

3. **PaymentMeans was correctly included**: Unlike all 11 prior T20 runs, this run included `<cac:PaymentMeans>` in the EHF XML, which populates `kidOrReceiverReference`. Verification GET confirmed the field was set. Score still pending at capture time.

## 8. Reusable Heuristics

1. **importDocument auto-generates PDF attachment** — do not waste a write uploading the original PDF. The voucher's `attachment` field is already populated after importDocument with `mimeType=application/pdf`. This saves 1 write per T20 run.

2. **PaymentMeans is the only remaining Check 5 fix** — the `<cac:PaymentMeans>` section with `<cbc:PaymentID>${invoiceNumber}</cbc:PaymentID>` and `<cac:PayeeFinancialAccount><cbc:ID>${bankAccount}</cbc:ID>` is what populates `kidOrReceiverReference`. Without it, Check 5 will always fail. This has been sandbox-verified and production-verified (in verification GET).

3. **Nynorsk "sjaa" = "sjå"** — Nynorsk prompts may use ASCII-only spelling "sjaa" instead of "sjå". Both should trigger the PDF supplier invoice trusted standard.

4. **Count writes accurately** — when documenting flow call counts, distinguish between writes (POST/PUT/DELETE) and reads (GET). GETs are free and should not be included in the write count. The old "6 writes" header was misleading and led agents to think they had a budget for 6 writes when only 4 are needed.

5. **Submissions may be "queued" at capture time** — the scoring system has a processing delay. Leaderboard diff may show no improvement if the submissions haven't been scored yet. Don't interpret queued=no-improvement as failure.
