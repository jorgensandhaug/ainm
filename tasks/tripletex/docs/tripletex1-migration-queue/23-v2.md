## Problem

Step 7 matches bank transactions to ledger postings by **amount only**:

```typescript
const matchPosting = allPostings1920.find((p: any) =>
  Math.abs(p.amount - csvAmount) < 0.01 && !usedPostingIds.has(p.id)
);
```

When a customer has 2+ invoices with identical outstanding amounts, `find()` picks the first posting — which can be the **wrong** invoice's posting. Production run 0c420db1 scored **0/10** because it swapped two Moe AS invoices this way.

## Solution

Replace amount-only matching with 3-layer deterministic matching:

**Layer 1 (customer lines):** Match by invoice number extracted from posting description.
- Posting descriptions: `"Betaling: Faktura nummer 4 til González SL (10004)"`
- Payment plan from Step 3 knows: CSV line[i] → invoiceNumber N
- Match: posting with `"Faktura nummer N"` in description → **deterministic, swap-proof**

**Layer 2 (supplier/non-invoice lines):** Match by amount + exclude OB posting.
- Filters out `"Inngående balanse"` posting (no bank txn for OB)
- Safe for non-customer lines (amounts typically unique)

**Layer 3 (fallback):** Pure amount match — identical to current code.
- Safety net if L1/L2 miss. Script can never do WORSE than today.

## Risks
- **Description format dependency:** If Tripletex changes the posting description format away from `"Faktura nummer N"`, Layer 1 stops matching. Layer 2+3 catch these cases (same as today's behavior).
